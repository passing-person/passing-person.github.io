# AI 비서 개발일지 #1 - 게임 개발을 도와줄 디스코드 봇을 서버에 올리기

이번 글은 게임 본편 개발일지라기보다는, 게임 개발을 계속하기 위해 필요한 도구를 만들기 시작한 기록이다.

최근에는 개인 게임 개발만 하는 것이 아니라, 게임잼, 블로그, 유튜브, 디스코드 봇 같은 작업들이 동시에 쌓이고 있다. 특히 게임잼을 진행하면서 느낀 것은, 개발 실력만큼이나 작업 관리가 중요하다는 점이었다.

짧은 시간 안에 여러 명이 함께 작업하다 보면, 지금 누가 무엇을 하고 있는지, 다음에 무엇을 해야 하는지, 어떤 문제가 남아 있는지 계속 정리해야 한다. 그런데 이 작업을 매번 직접 하는 것도 꽤 부담이 된다.

그래서 단순한 TODO 앱이 아니라, 개발 내용을 정리하고 다음 작업을 제안해줄 수 있는 AI 비서를 만들어보고 싶어졌다.

## 왜 AI 비서인가

게임 개발은 단순히 코드를 작성하는 작업만으로 끝나지 않는다.

현재 내가 동시에 신경 쓰고 있는 작업은 대략 다음과 같다.

* 개인 게임 개발
* 게임잼
* 블로그 개발일지
* 유튜브 영상 제작
* 디스코드 봇
* AI 개발 비서

각 작업이 완전히 분리되어 있으면 차라리 관리하기 쉽다. 하지만 실제로는 서로 연결되어 있다.

게임 개발을 하면 블로그에 기록해야 하고, 영상으로 정리할 수도 있다. 게임잼을 하면 협업 기록과 회고가 생긴다. 디스코드 봇은 나중에 개발 알림이나 작업 요약 도구로 확장할 수 있다.

결국 필요한 것은 단순한 메모장이 아니라, 개발 흐름을 계속 정리해주는 도구에 가깝다.

그래서 AI 비서를 만들기로 했다.

## 왜 디스코드 봇인가

AI 비서를 만들 수 있는 방식은 여러 가지가 있다.

웹앱으로 만들 수도 있고, 별도의 데스크톱 앱으로 만들 수도 있다. 하지만 처음부터 너무 큰 형태로 만들면 완성하기 어렵다.

그래서 첫 번째 형태는 디스코드 봇으로 정했다.

디스코드는 이미 게임 개발이나 커뮤니티 운영에서 자주 쓰이는 도구다. 명령어를 입력해서 바로 반응을 받을 수 있고, 나중에 알림, 작업 기록, 요약 기능을 붙이기도 좋다.

예상하는 기능은 다음과 같다.

* 오늘 할 일 정리
* 개발 작업 요약
* 남은 TODO 확인
* 게임잼 작업 기록 정리
* 블로그 글감 정리
* 서버 상태 확인
* AI 응답 기능 연결

아직 이 기능들이 완성된 것은 아니지만, 방향은 이쪽이다.

## 첫 번째 문제: 로컬 실행의 한계

처음에는 봇을 그냥 내 컴퓨터에서 실행했다.

터미널에서 봇을 켜면 디스코드에 온라인으로 표시되고, 명령어에도 반응한다. 테스트 단계에서는 이 방식으로 충분하다.

하지만 실제로 사용하려고 하면 문제가 생긴다.

내 컴퓨터를 끄면 봇도 같이 꺼진다. 밖에서 사용하기도 어렵고, 항상 켜진 상태로 유지할 수도 없다.

AI 비서라면 필요할 때 언제든 접근할 수 있어야 한다. 그렇다면 로컬 실행만으로는 부족하다.

그래서 서버가 필요해졌다.

## 서버 구매

이번에는 Vultr에서 Ubuntu 서버를 하나 구매했다.

현재 서버 사양은 대략 다음과 같다.

| 항목       | 내용               |
| -------- | ---------------- |
| Provider | Vultr            |
| Location | Seoul            |
| OS       | Ubuntu 24.04 LTS |
| CPU      | 1 vCPU           |
| RAM      | 2GB              |
| Storage  | 50GB NVMe        |

엄청 강한 서버는 아니지만, 디스코드 봇이나 간단한 자동화 도구를 돌리기에는 충분한 수준이다.

나중에 더 많은 기능을 붙이거나 여러 서비스를 동시에 돌리게 되면 부족할 수도 있지만, 지금 단계에서는 적절하다고 판단했다.

## Docker를 사용한 이유

서버에 봇을 올리는 방법은 여러 가지가 있다.

가장 단순한 방법은 서버에 직접 Python이나 Node.js 환경을 설치하고, 필요한 패키지를 설치한 뒤 봇을 실행하는 것이다.

하지만 이번에는 Docker를 사용해보기로 했다.

Docker는 처음 써보는 도구라서 이미지와 컨테이너의 차이부터 헷갈렸다. 그래도 사용해보기로 한 이유는 명확했다.

* 실행 환경을 고정할 수 있다.
* 서버 환경을 덜 오염시킬 수 있다.
* 나중에 다른 서버로 옮기기 쉽다.
* 봇, 웹 서버, 데이터베이스 등을 분리해서 관리하기 좋다.
* 실제 서비스 배포 방식에 더 가깝다.

핵심은 간단하다.

봇이 실행되는 환경을 컨테이너로 묶어두면, 서버에서도 같은 방식으로 실행할 수 있다.

## 현재 상태

현재는 로컬에서만 실행하던 디스코드 봇을 서버에서 실행할 수 있는 기반을 만들고 있다.

아직 완성된 AI 비서라고 부르기에는 부족하다. 지금 단계에서는 봇 기능 자체보다, 봇을 항상 접근 가능한 환경에 올리는 것이 더 중요했다.

현재까지의 진행 상황은 다음과 같다.

| 항목           | 상태 |
| ------------ | -- |
| 디스코드 봇 개발 시작 | 진행 |
| 로컬 실행 테스트    | 완료 |
| 서버 구매        | 완료 |
| Ubuntu 서버 준비 | 완료 |
| Docker 사용    | 시작 |
| 서버 배포 구조 구성  | 진행 |
| AI 비서 기능 추가  | 예정 |

이번 작업의 핵심은 “AI 기능을 완성했다”가 아니다.

로컬에서만 돌아가던 봇을 서버 기반으로 옮기고, 앞으로 AI 비서로 확장할 수 있는 첫 단계를 만든 것이다.

## 앞으로 추가할 기능

앞으로 붙이고 싶은 기능은 다음과 같다.

* 작업 목록 저장
* 오늘 할 일 출력
* 개발 기록 요약
* 블로그 글감 정리
* 게임잼 작업 정리
* 서버 로그 확인
* AI 응답 기능 연결
* GitHub나 개발 프로젝트와의 연동

장기적으로는 단순한 챗봇이 아니라, 게임 개발을 계속하기 위한 개인 개발 비서에 가깝게 만들고 싶다.

## 당분간의 개발일지 방향

최근에는 게임잼 기간과 여러 작업이 겹치면서 개인 게임 개발 본편의 진척이 크지 않았다.

그래서 당분간은 게임 본편 개발일지만 올리기보다는, 서브 프로젝트로 AI 비서 개발기도 함께 올리려고 한다.

이 작업은 게임 개발과 완전히 별개의 일이 아니다. 오히려 앞으로 게임 개발을 더 안정적으로 계속하기 위한 기반 작업에 가깝다.

이번 글과 영상은 그 첫 번째 기록이다.

## 정리

이번 개발일지의 핵심은 다음과 같다.

* 게임잼 이후 작업 관리의 필요성을 느꼈다.
* 개발 내용을 정리해줄 AI 비서를 만들기로 했다.
* 첫 번째 형태로 디스코드 봇을 선택했다.
* 로컬 실행만으로는 24시간 사용이 어려웠다.
* Vultr 서버를 구매했다.
* Docker를 사용해 서버 배포 구조를 만들기 시작했다.
* 당분간은 AI 비서 개발기를 서브 프로젝트로 기록할 예정이다.

다음에는 이 봇에 어떤 기능을 붙일지, 그리고 실제로 개발 작업을 어떻게 도와줄 수 있을지 정리해볼 생각이다.
