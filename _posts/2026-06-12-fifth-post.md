# 균열 골렘, DB 연결기, 설정 UI, 아이콘 정리

오늘은 전투 콘텐츠 확장, 제작 편의성 개선, UI 설정, 아트 리소스 정리를 함께 진행했다.

핵심 작업은 다음과 같다.

```text
1. GameDatabaseSO 자동 연결기 제작
2. 균열 골렘 전투 구조 구현 및 테스트
3. 자폭 / 자기 피해 / AI 카드 사용 판단 수정
4. 균열 골렘 관련 이벤트 추가
5. Title 설정 UI 코드 작성
6. 상태이상 / 카드 / 인챈트 아이콘 적용
```

# 1. GameDatabaseSO 자동 연결기

먼저 ScriptableObject가 늘어나면서 반복되던 DB 수동 등록 문제를 줄이기 위해 GameDatabaseSO 자동 연결기를 만들었다.

이번 자동 연결기의 범위는 의도적으로 좁게 잡았다.

```text
대상:
- GameDatabaseSO

제외:
- ZoneSO 자동 등록
- RewardTable 자동 생성
- CombatSO 자동 매칭
- 런타임 자동 로딩
```

자동 연결기는 프로젝트 내 주요 SO를 검색해서 GameDatabaseSO의 리스트에 등록한다.

자동 등록 대상은 다음과 같다.

```text
CardDataSO
EnchantDataSO
StatusDataSO
SynergySO
RewardTableSO
EventSO
EventChoiceSO
ZoneSO
CombatSO
CombatEnemySO
EnemyAIProfileSO
AttackAnimationSO
```

이 과정에서 `test`가 붙은 SO는 기본적으로 제외하도록 했다.

```text
필터링 기준:
- 경로에 Test / Tests 포함
- 파일명에 test 포함
- asset.name에 test 포함
```

이를 통해 테스트용 SO가 실제 게임 DB에 섞이는 문제를 줄일 수 있게 되었다.

# 2. 균열 골렘 전투 구조

오늘의 주요 전투 콘텐츠는 균열 골렘이었다.

처음에는 방어형 적이나 원거리형 적을 추가하는 것도 고려했지만, 기존 골렘이 이미 방어형 역할을 일부 맡고 있고 고블린 투척병이 원거리형 역할을 맡고 있었기 때문에 역할이 겹쳤다.

따라서 오늘은 새로운 축을 가진 적으로 균열 골렘을 우선 제작했다.

균열 골렘의 핵심 기믹은 다음과 같다.

```text
1. 전투 시작 시 균열 상태를 가진다.
2. 피해를 받을 때마다 균열 수치가 증가한다.
3. 균열 수치에 따라 공격력이 증가한다.
4. 균열이 일정 수치 이상이면 필중 자폭기를 사용한다.
```

이를 위해 상태이상 시스템에 `OnAfterTakeDamage` 트리거를 추가했다.

```text
피해 계산
→ Guard 적용
→ 실제 HP 감소
→ 실제 피해가 1 이상이면 OnAfterTakeDamage 발동
```

이 구조 덕분에 Guard로 완전히 막힌 피해는 균열을 증가시키지 않고, 실제 체력 피해가 들어간 경우에만 균열이 증가한다.

---

# 3. 상태이상이 상태이상을 부여하는 구조

균열은 Resource형 상태이상으로 동작한다.

기존 Resource 상태는 수치 저장/소비용에 가까웠기 때문에, 피해를 받은 뒤 다시 자기 자신에게 균열을 부여하는 구조가 필요했다.

이를 위해 상태이상 효과에서 다른 상태이상을 부여할 수 있는 효과를 추가했다.

```text
ApplyStatusFromStatusEffectSO
```

이 효과를 통해 균열 상태는 다음처럼 작동한다.

```text
OnAfterTakeDamage 발동
→ 자기 자신에게 균열 +1 부여
→ 균열 power 증가
```

즉, 균열은 단순한 디버프가 아니라 전투 중 계속 누적되는 리소스 상태가 되었다.

---

# 4. 자폭 카드와 자기 피해 판정

균열 골렘의 필살기는 자폭기다.

원래 의도한 구조는 다음과 같았다.

```text
균열이 충분함
→ 적에게 필중 피해
→ 자기 자신에게 큰 피해
```

그러나 기존 피해 처리 구조에서는 자기 자신에게 피해를 주는 방식이 제대로 작동하지 않았다.

문제는 DamageEffect가 실제로는 공간 기준 공격인데, 자기 피해 판정이 targetType이나 별도 조건에 묶여 있었다는 점이다.

수정 후에는 자기 피해를 다음 기준으로 처리하도록 바꾸었다.

```text
DamageEffect는 공간 기준이다.
공격 범위 안에 actor 자신이 있고,
canHitSelf가 true라면 자기 자신도 피해를 받는다.
```

이제 폭탄, 장판, 자폭처럼 공격 범위가 고정되어 있는 효과에서 자기 자신이 범위 안에 들어오면 피해를 받을 수 있다.

또한 상대가 회피하더라도 자신이 공격 범위 안에 있으면 자기 피해는 처리되도록 했다.

```text
상대가 회피
→ OnMiss 처리
→ 그래도 자신이 범위 안에 있으면 자기 피해 적용
```

# 5. 카드 자체 사용 조건

자폭 카드가 균열 수치가 낮을 때도 AI에 의해 사용되는 문제가 있었다.

이를 해결하기 위해 카드 자체에 사용 조건을 추가했다.

```text
CardDataSO.playConditions
```

예를 들어 자폭 카드는 다음 조건을 가진다.

```text
SelfHasStatusResourceConditionSO
- resourceStatus: 균열
- requiredAmount: 자폭 기준 수치
```

이제 균열이 부족하면 해당 카드는 아예 사용할 수 없다.

```text
균열 부족
→ 카드 사용 불가
→ AI도 선택하지 않음
```

이 방식은 branch 내부에서 조건을 나누는 것보다 명확하다.
자폭 카드 자체가 조건부 카드가 되기 때문에, AI가 낮은 균열 상태에서 의미 없는 자폭 카드를 쓰는 일을 막을 수 있다.

---

# 6. AI 카드 사용 판단 수정

AI가 카드 순환을 위해 낮은 가치의 카드도 사용할 수 있어야 하는 상황이 있다.

처음에는 점수 하한을 기준으로 카드 순환 여부를 판단했지만, 실제로는 현재 마나 상황을 보는 편이 더 맞았다.

수정 후 AI는 다음 기준으로 판단한다.

```text
1. 카드 점수가 충분히 높으면 사용
2. 점수가 낮더라도 패스하면 마나가 낭비되는 상황이면 사용
3. 패스가 의미 있는 상황이면 패스 가능
```

예시는 다음과 같다.

```text
현재 마나가 이미 최대치
→ 패스해도 의미 없음
→ 낮은 가치 카드라도 사용 가능

패스 보너스를 받으면 최대 마나를 초과함
→ 마나 낭비 발생
→ 낮은 가치 카드라도 사용 가능

현재 마나가 많이 비어 있음
→ 패스할 가치 있음
→ 낮은 가치 카드는 사용하지 않을 수 있음
```

이를 통해 AI가 무조건 좋은 카드만 기다리며 패스하는 문제를 줄이고, 동시에 자폭처럼 조건이 필요한 카드는 조건 만족 전에는 사용하지 않게 만들었다.

# 7. 기존 골렘 조정

기존 골렘은 방어형 적의 역할을 어느 정도 맡고 있었다.

따라서 받는 피해 감소를 유지하는 대신 단순히 체력을 올리는 방향으로 조정했다.

```text
기존 골렘:
- 받는 피해 감소 제거
- 기본 체력 증가
```

이렇게 하면 기존 골렘은 단순한 고체력 적으로 남고, 균열 골렘은 누적형 위협 적으로 차별화된다.

# 8. 갈라진 석상 이벤트

균열 골렘 관련 이벤트로 `갈라진 석상`을 추가했다.

이벤트 구조는 기존 이벤트 흐름을 따른다.

```text
루트 EventSO
→ 선택지
→ 결과 EventSO
→ 단일 확인 선택지
→ Combat / Reward
```

이번에는 선택지를 두 개만 남겼다.

```text
1. 석상의 균열을 건드린다
2. 멀리서 관찰한다
```

삭제한 선택지는 다음과 같다.

```text
떨어진 파편을 챙긴다
지나간다
```

`석상의 균열을 건드린다`는 균열 골렘 전투로 이어진다.

`멀리서 관찰한다`는 보상 결과로 이어지지만, 보상 테이블은 자동으로 연결하지 않았다.
보상은 이후 직접 연결할 수 있도록 비워 두었다.

# 9. Title 설정 UI 코드

사운드 시스템과 BGM 연결이 끝났기 때문에, 볼륨 설정을 위한 코드도 추가했다.

설정 항목은 세 가지다.

```text
Master Volume
BGM Volume
SFX Volume
```

AudioManager에는 볼륨 저장과 로드 기능을 추가했다.

```text
SetMasterVolume
SetBgmVolume
SetSfxVolume

SaveVolumeSettings
LoadSavedVolumeSettings
ResetSavedVolumeSettings
```

저장에는 PlayerPrefs를 사용한다.

```text
ProjectEnchant.Audio.MasterVolume
ProjectEnchant.Audio.BgmVolume
ProjectEnchant.Audio.SfxVolume
```

Title 화면에 직접 배치하는 작업은 아직 하지 않았다.
대신 설정 패널 프리팹을 생성할 수 있는 Editor 스크립트와, 슬라이더를 연결할 수 있는 `AudioSettingsUI` 코드를 준비했다.

씬 배치는 이후 직접 진행할 수 있게 코드만 작성해 두었다.
